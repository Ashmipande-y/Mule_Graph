# IBM synthetic AML benchmark — prepared dataset (runtime data)

**This is synthetic data. It is not real UPI customer data.** Every surface
in this application that displays it must label it "IBM synthetic AML
benchmark," never "real UPI transactions."

The bulk data files in this directory are gitignored (regenerable, not
source-controlled — see `.gitignore`). This README is tracked so the
integration is discoverable even when the data isn't present locally.

## What's here (once populated)

| File | Rows | Purpose |
| --- | --- | --- |
| `transfers_inr.csv` | 27,511 | The runtime source of truth for the "IBM AML dataset" mode — inter-account ACH/Wire transfers only (self-transfers and other channels excluded). Backend-facing, analogous to `data/demo_transactions.json`'s role for the canonical demo. |
| `transfer_labels_and_splits.csv` | 27,511 | Ground-truth `is_laundering` label + chronological split assignment (`train`/`validation`/`test`/`outside_primary_period`) per transaction id. Kept **separate** from `transfers_inr.csv` — never merged into what the graph/table displays as a "score." |

## Provenance

- Source: [IBM AML on Kaggle](https://www.kaggle.com/datasets/ealtman2019/ibm-transactions-for-anti-money-laundering-aml)
  (`ealtman2019/ibm-transactions-for-anti-money-laundering-aml`), version 8,
  file `HI-Small_Trans.csv`, SHA-256 `b19d39f515523373f991b689c07e11e7b0b95c17a2c27a87d91584ae16c5b040`
  (see `source_manifest.json`).
- Synthetic data generated by IBM's virtual-world model. License: **CDLA-Sharing-1.0**.
- Supporting docs: [IBM/AML-Data](https://github.com/IBM/AML-Data), [the dataset paper](https://arxiv.org/abs/2306.16424).
- Currency: rows selected where both `Payment Currency` and `Receiving Currency`
  are `Rupee`, mapped to this project's `INR` convention. **No foreign-exchange
  conversion was performed** — these are the source's own Rupee-denominated rows.
- Money: amounts are stored as **integer `amount_paise`** (e.g. ₹753,279.46 →
  `75327946`). No rounding, clipping, or scaling. Never put a paise value into
  the canonical demo's whole-rupee `amount` field — see
  `frontend/lib/services/amlClient.ts` / `backend/app/services/aml_dataset.py`
  for the explicit, separate contract this dataset uses.
- Time: source timestamps have **minute-level precision** and **no specified
  timezone**. UTC is an explicit *simulation-timeline assumption* here, not a
  verified real-world timezone — timestamps are normalized to
  `YYYY-MM-DDTHH:MM:00Z` (the trailing `:00` is formatting, not added precision).
- Channels: original payment formats (ACH, Wire, Cheque, etc.) are preserved
  as-is. **No transaction is relabeled as UPI.**
- Chronological splits (`ml/data/aml/splits/`, used for model training —
  see `ml/aml_baseline/`): train = Sep 1–6 2022 (16,666 rows, 83 positive),
  validation = Sep 7–8 (5,345 rows, 25 positive), test = Sep 9–10 (5,479 rows,
  18 positive). 21 rows after Sep 10 (19 positive) are excluded from the
  primary split to avoid an unrepresentative late-period label distribution.

## Regenerating this data

This project does not redistribute IBM's raw source file and never fetches
it automatically (Kaggle requires your own account/credentials, which this
project never asks for, stores, or invents). To regenerate:

1. Obtain `HI-Small_Trans.csv` (version 8) from
   [Kaggle](https://www.kaggle.com/datasets/ealtman2019/ibm-transactions-for-anti-money-laundering-aml)
   yourself, matching the SHA-256 above.
2. Run the tracked preparation script (from the repo root, with
   `ml/requirements.txt` installed — see `ml/aml_baseline/README.md` for the
   venv setup):
   ```powershell
   ml/.venv/Scripts/python.exe scripts/prepare_aml_dataset.py --source /path/to/HI-Small_Trans.csv
   ```
   This verifies the source file's hash and schema, converts amounts to
   exact integer paise, normalizes timestamps (UTC assumed, minute
   precision — see "Time" above), computes the causal feature set, and
   writes every file in the table above plus `ml/data/aml/splits/`,
   directly in place. See the script's own module docstring for the full
   list of validations it performs, and
   `scripts/test_prepare_aml_dataset.py` for a data-driven proof that its
   feature computation reproduces the already-committed
   `ml/data/aml/splits/*_features.csv` values exactly.
3. Save the CDLA-Sharing-1.0 license text (e.g. from
   [cdla.dev/sharing-1-0](https://cdla.dev/sharing-1-0/)) as
   `data/aml/LICENSE-DATA.txt` yourself — the script does not generate or
   fetch license text.

See `ml/aml_baseline/README.md` for the model training command once this
data is in place.
